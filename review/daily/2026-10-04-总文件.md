#### 1. RADIO-ViPE: Online Tightly Coupled Multi-Modal Fusion for Open-Vocabulary Semantic SLAM in Dynamic Environments【摘要+部分章节】
- 链接：https://arxiv.org/abs/2604.26067 （PDF：https://arxiv.org/pdf/2604.26067）
- 学科类别（arXiv 页面）：主类 cs.CV；当前 v1
- 提交日期：2026-04-28（cs；早于近 2–3 周范围，已注明真实日期）
- 作者：Zaid Nasser, Mikhail Iumanov, Tianhao Li, Maxim Popov, Jaafar Mahmoud, Sergey Kolyubin（Biomechatronics and Energy-Efficient Robotics (BE2R) Lab, ITMO University）
- **方向归属**：① 语义 SLAM 与三维重建（无标定单目开放词汇语义 SLAM；RADIO/RADSeg 多模态嵌入与几何紧耦合；**兼**开放词汇 grounding，主贡献是在线动态语义 SLAM 而非离线语言高斯蒸馏）。
- **要解决的问题**：既有开放词汇 3D 方法多离线、依赖标定 RGB-D/位姿且常假设静态场景；动态/被挪动物体破坏数据关联；缺少可部署的无标定单目在线语义 SLAM。
- **方法**：RADIO-ViPE——原始单目 RGB；(1) 在滑动窗口因子图中紧耦合几何（光流/深度/位姿）与 RADIO 高维视觉–语言嵌入；(2) RADSeg 滑动窗语义特征 + PCA 压缩（默认 D=256）；(3) 时序稳定性场 \(S_i(u)\) 驱动三区间 Barron 自适应稳健核（静态 / 可挪动 / 主动运动），降权动态关联；(4) 将点特征投影到 SigLIP 空间做开放词汇查询。叙述运行约 **8–10 FPS**；评测硬件 Intel Xeon Gold 5320 + RTX 4090。变体：仅嵌入项为 RADIO-ViPE；加自适应核为 RADIO-ViPE\(^{\mathrm{ark}}\)。
- **实验数据**：动态 TUM-RGBD；Replica 开放词汇语义分割（协议对齐 RayFronts，8 场景 office0–4 / room0–2）；对比 Dyna-SLAM、DLD-SLAM、V3D-SLAM、DGS-SLAM、RoDyn-SLAM、DynaMON、ViPE (SAM)、RayFronts、ConceptFusion/Graphs、HOV-SG、NACLIP-3D、Trident-3D 等。
- **作者自报关键数字**（对照 PDF 表 II–III 与实验段）：
  - 表 II（TUM-RGBD ATE cm，↓）：RADIO-ViPE 行末 Average **1.90**；RADIO-ViPE\(^{\mathrm{ark}}\) Average **1.63**（同表 DynaMON avg **1.76**；ViPE (SAM) **2.17**）。全文行（作者表序，含 8 序列+Average）：RADIO-ViPE **1.90 / 3.50 / 3.10 / 0.55 / 1.15 / 2.72 / 1.60 / 0.53 / 1.90**；RADIO-ViPE\(^{\mathrm{ark}}\) **1.55 / 3.39 / 1.96 / 0.50 / 0.98 / 2.65 / 1.44 / 0.56 / 1.63**。
  - 表 III（Replica，RayFronts 协议）：RADIO-ViPE Without-BG mIoU / f-mIoU / Acc **24.25 / 50.63 / 59.25**；With-BG **19.00 / 37.13 / 48.38**。RADIO-ViPE\(^{\mathrm{GT}}\)（有 GT 深度/位姿/标定）Without-BG **29.51 / 52.24 / 59.80**；With-BG **28.19 / 54.44 / 65.21**。正文称相对 GT 变体 Without-BG 的 f-mIoU/Acc 仅约 **1–2%** 差距；作者自报整体排 top-3（RayFronts Without-BG mIoU **39.37** 仍最高）。
  - Fig.4 叙述：PCA D=256 相对全维 \(\Delta\)mIoU **<1%**。
- **作者承认的局限 / 边界**：With-BG 设定下降更明显，归因结构性类别（墙/地板）分割困难；未见独立 Limitations 小节。摘要页所述项目页 https://be2rlab.github.io/radio_vipe 未能打开（未能核实）；候选仓库 `github.com/BE2RLab/radio_vipe` 指向的是无关项目，**未能核实**为论文官方代码。
- **阅读程度**：【摘要+部分章节】，非全文。实际读了：摘要、方法（因子图/嵌入项/自适应核）、表 II–III、实验与结论；两栏混排导致表 II 列名与数字行需对照版面；未通读全部参考文献与全部定性图。

#### 2. OnlinePG: Online Open-Vocabulary Panoptic Mapping with 3D Gaussian Splatting【摘要+部分章节】
- 链接：https://arxiv.org/abs/2603.18510 （PDF：https://arxiv.org/pdf/2603.18510）；CVPR 2026 Open Access 页可打开：https://openaccess.thecvf.com/content/CVPR2026/html/Zhai_OnlinePG_Online_Open-Vocabulary_Panoptic_Mapping_with_3D_Gaussian_Splatting_CVPR_2026_paper.html
- 学科类别（arXiv 页面）：主类 cs.CV；Comments：**CVPR 2026**；当前 v1
- 提交日期：2026-03-19（cs；早于近 2–3 周范围，已注明真实日期）
- 作者：Hongjia Zhai, Qi Zhang, Xiaokun Pan, Xiyu Zhang, Yitong Dong, Huaqi Zhang, Dan Xu, Guofeng Zhang（Zhejiang University / VIVO BlueImage Lab / HKUST）
- **方向归属**：② 开放词汇和大模型驱动的语义地图（在线开放词汇全景建图；3DGS + VLM 掩码/特征；**非**多传感器占用预测主贡献）。
- **要解决的问题**：开放词汇 3D 理解多为离线或缺实例级；在线系统难把噪声 2D VLM 先验融成一致 3D 实例与语言场。
- **方法**：OnlinePG——RGB-D 流；(1) 滑动窗口 local-to-global；(2) 几何+语义多线索 3D segment clustering graph，把窗内不一致片段聚成实例；(3) 局部 3DGS 建显式空间属性网格，经双向二分图匹配融入全局实例图；(4) 网格内融合 VLM 特征支撑开放词汇查询。正文叙述（不含 VLM 前向）：简单场景约 **18 FPS**、复杂约 **10 FPS**；渲染优化约 410 ms / 聚类 350 ms / 全局融合 1400 ms（每若干关键帧）。
- **实验数据**：ScanNetV2、Replica；对比 LangSplat、OpenGaussian、OpenScene、InstanceGaussian、PanoGS、O2V-Mapping、OnlineAnySeg 等。
- **作者自报关键数字**（对照 PDF 表 1–3 / 附录表 4–5）：
  - 表 1：Ours（在线+全景）ScanNetV2 mIoU / mAcc / PRQ(T) / PRQ(S) **48.48 / 66.01 / 37.97 / 41.81**；Replica **47.93 / 54.94 / 41.02 / 12.83**。正文称在线方法中语义 mIoU/mAcc 最优；相对 O2V-Mapping（ScanNet mIoU **33.74**）与 OnlineAnySeg（**31.28**）有明显提升；离线 PanoGS ScanNet mIoU **50.72** 仍略高。
  - 表 2（ScanNet 匹配消融 PRQ T/S）：Full 双向 **37.97 / 41.81**；NN **24.67 / 22.98**；仅前向 **35.83 / 38.40**；仅后向 **33.71 / 42.72**。
  - 表 3：Full mIoU / PRQ(T) / PRQ(S) **48.48 / 37.97 / 41.81**；去掉 Feature Grid F 降至 **30.40 / 26.71 / 24.92**（版面行）。
  - 附录表 4–5：Ours 各场景 FPS 约 **12–18**（Replica）/ **13–18**（ScanNet）；OnlineAnySeg 在 Replica 仅 office1 的 FPS 更高（20.94 vs 18.22），其余 7 个场景 Ours 更高；在 ScanNetV2 全部 10 个场景 FPS 均更高（15.57–26.44 vs Ours 13.33–18.83）；表中 FPS 不含 VLM 推理。OnlineAnySeg 的 mIoU 在 ScanNetV2 各场景均较低，在 Replica 多数场景较低（office0 / office1 / office4 例外）。
- **作者承认的局限 / 边界**：(1) 当前不能重建动态物体；(2) 像先前工作一样需要深度与位姿输入；未来拟探索无位姿/无深度前馈重建。未见已核实官方代码 URL。
- **阅读程度**：【摘要+部分章节】，非全文。实际读了：摘要、方法概述、表 1–3、局限与结论、附录表 4–5 效率行；未通读全部定性图与全部参考文献。

#### 3. GaussianOcc3D: A Gaussian-Based Adaptive Multi-modal 3D Occupancy Prediction【摘要+部分章节】
- 链接：https://arxiv.org/abs/2601.22729 （PDF：https://arxiv.org/pdf/2601.22729）
- 学科类别（arXiv 页面）：主类 cs.CV；当前 v1
- 提交日期：2026-01-30（cs；早于近 2–3 周范围，已注明真实日期；③ 方向近期可核实的新论文不足，故收录）
- 作者：A. Enes Doruk, Hasan F. Ates
- **方向归属**：③ 多传感器融合感知（相机 + LiDAR 语义占用；共享 3D 高斯原语替代稠密体素/BEV）。
- **要解决的问题**：单模态折中语义与几何；多模态融合面临模态异构、空间错位与体素/BEV 表示代价；纯视觉高斯易有虚假几何。
- **方法**：GaussianOcc3D——固定约 **25,600** 高斯；(1) LDFA：深度向可变形采样把稀疏 LiDAR 抬到高斯；(2) EBFS：熵引导特征平滑；(3) ACLF：不确定性感知的相机–LiDAR 自适应重加权；(4) Gauss-Mamba Head：选择性状态空间做全局上下文后 splat 到体素占用。训练叙述：A100，20 epochs，bs=1；相机 ResNet101-DCN + FPN；LiDAR 聚合前 10 sweeps。
- **实验数据**：SurroundOcc / Occ3D（nuScenes）、SemanticKITTI；对比 MonoScene、SurroundOcc、OccFormer、Co-Occ、M-CONet、OccMamba、OccFusion、GaussianFormer / GaussianFormer3D 等。
- **作者自报关键数字**（对照摘要、正文主结果段与表 IV–VIII）：
  - 摘要/贡献列表（作者自报）：Occ3D / SurroundOcc / SemanticKITTI mIoU **49.4% / 28.9% / 25.2%**。
  - SurroundOcc（表 I / 正文）：Ours **28.9** mIoU；相对 M-CONet **+4.2**；Co-Occ 与 GaussianFormer3D 同文称约 **27.1**。
  - Occ3D（表 II / 正文）：Ours **49.4** mIoU；相对 OccFusion **48.7**。
  - SemanticKITTI（表 III / 正文）：Ours **25.2**；OccMamba **24.6**；Co-Occ **24.4**；M-CONet **20.4**。
  - 表 V 恶劣条件：Rainy / Night mIoU **27.1 / 15.9**。
  - 表 VII 模型复杂度：Ours **68.1M** 参数、Latency **427 ms**（同表 GaussianFormer 52.4M / 342 ms；OccMamba 92.3M / 531 ms）。
  - 表 VIII 消融（SurroundOcc mIoU）：基线 **20.2** → +LiDAR **24.1** → +ACLF **26.1** → +LDFA **28.4** → +EBFS **28.6** → +Gauss-Mamba **28.9**。
  - 表 IV 融合方式：ACLF **28.9** vs Addition **28.0** / Concatenation **28.2**。
- **作者承认的局限 / 边界**：正文未见独立 Limitations 小节；结论强调高斯桥接稀疏几何与稠密占用。PDF 首页摘要末 “Code” 链接指向 github.com/enesdoruk/GaussianOcc3D；该仓库 README 写 “CODE COMING SOON”，代码与预训练模型尚未发布。
- **阅读程度**：【摘要+部分章节】，非全文。实际读了：摘要、方法要点、主结果叙述、表 IV–VIII、结论；表 I–III 逐类大表因双栏/插图交错未逐格全核，主 mIoU 以摘要+正文明确句+消融表为准。
